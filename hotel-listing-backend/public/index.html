Hotel Listing API

A REST API for hotel listings, with login and image uploads. It uses no database: data is saved to data/db.json and images to uploads/.

Base URLhttp://localhost:4000
MethodEndpointAuthDescription
POST/register–Create an account
POST/login–Log in, returns token
GET/hotels–All listings (filter, search, pagination)
GET/hotels?userId=3–One user's properties
GET/hotels/:id–One listing
POST/hotelsTokenAdd a property (body must include userId)
PATCH/hotels/:idOwnerEdit a property
DELETE/hotels/:idOwnerDelete a property

Authentication

Call /register or /login to get an accessToken. Send it in the Authorization header on every request marked 🔒 Token or 🔒 Owner. Tokens last 7 days.

Header
Authorization: Bearer <accessToken>

Errors

Every error response has the same shape: { "message": "..." }

StatusMeaning
400Invalid input, for example a missing field, an email that is already registered, a wrong password, or a file that isn't an image
401The token is missing, invalid or expired
403You are not the owner, or userId doesn't match the logged-in user
404Hotel not found
500Server error

GET/hotels?userId=3Public

My properties: pass the logged-in user's id. You can combine it with any other parameter, e.g. /hotels?userId=3&_page=1&_limit=10.

GET/hotels/:idPublic

Returns a single listing object, or 404 if it doesn't exist.

POST/hotels🔒 Token

Required: userId (it must equal the logged-in user's id) and name. Every other field is optional. See Hotel fields for the full list.

To upload images, send the request as FormData, with files in images. Without images, plain JSON works too. See Hints.

The response is 201 with the created hotel. The server sets id, image, createdAt and updatedAt.

PATCH/hotels/:id🔒 Owner

Send only the fields you want to change. Only the owner can edit. id, userId and createdAt cannot be changed. PUT works the same way.

Images you wantWhat to send
Add new imagesUpload files in images; they are appended
Remove some imagesSend images = the URLs to keep; the rest are deleted
Remove all imagesSend images as an empty string (form-data) or [] (JSON)
Leave images as they areDon't send images at all
JSON
{ "price": 99, "description": "Now with breakfast" }
DELETE/hotels/:id🔒 Owner

Deletes the listing and its image files. Returns {}.

Filter, search & pagination

These work on GET /hotels and can be combined with each other.

WhatParameterExample
Search (all fields)q or search?q=beach
Exact matchfield=value?city=Goa
Match any of several valuesrepeat the key?city=Goa&city=Delhi
Greater / less than_gte _lte _gt _lt?price_gte=50&price_lte=200
Contains_like?name_like=inn
Not equal_ne?city_ne=Goa
Sort_sort, _order?_sort=price&_order=desc
Pagination_page, _limit (or page, limit)?_page=2&_limit=10
Paginated responses include an X-Total-Count header with the total number of matches, and a Link header with first, prev, next and last page URLs. Use them to work out the number of pages: Math.ceil(total / limit).

Hints

TaskHow
Upload imagesUse FormData and add each file under the same key: form.append("images", file). Put the other fields in the same form.
Content-TypeWith FormData, don't set Content-Type; the browser sets it for you. With JSON, set application/json.
TokenAdd Authorization: Bearer <accessToken> to add, edit and delete requests.
Arrays in FormDataSend them as JSON: form.append("amenities", JSON.stringify(["wifi","pool"]))
Numbers & booleansAppend them normally, e.g. "120" or "true". The server converts them to real numbers and booleans.
Show imagesUse hotel.image as the cover photo and hotel.images for a gallery. These are full URLs, so use them directly in <img src>.
Edit imagesAdding new files appends them. To remove images, send images with the URLs you want to keep (see PATCH).
My propertiesGET /hotels?userId=<user.id>
PaginationAdd _page and _limit. Read the total from the X-Total-Count header; the number of pages is Math.ceil(total / limit).
Search box?q=<text> searches every field, including name, city and description.
Price filter?price_gte=1000&price_lte=5000
Keep the loginSave accessToken and user (in localStorage, for example). A 401 response means the token has expired, so send the user back to login.
